虚拟化

# 虚拟化介绍
> [Virtualization Explained](https://www.youtube.com/watch?v=UBVVq-xz5i0) 

虚拟化：将一台物理计算机的硬件资源（CPU、内存、磁盘、网卡）进行抽象、拆分、隔离，虚拟出多台独立的虚拟计算机。
核心目的：资源复用、隔离、提高利用率、按需分配
虚拟化 vs 物理机 vs 容器（核心区别）
- 物理机：独占硬件，资源浪费严重
- 虚拟机（KVM/VMware/Xen）：模拟完整硬件，拥有独立内核，强隔离
- 容器（Docker/LXC）：共享宿主机内核，只是进程级隔离，最轻量

# 虚拟化三大技术类型
## 全虚拟化（Full Virtualization）
完全模拟一套完整硬件，虚拟机系统不需要修改，不知道自己是虚拟机。
代表：KVM、VMware ESXi、VirtualBox
优点：兼容性极强，任意系统都能装
缺点：早期纯软件模拟性能差，现在依靠 CPU 硬件虚拟化（VT-x/AMD-V）性能接近物理机

## 半虚拟化（Para Virtualization）
不需要完整模拟硬件，虚拟机内核需要安装特殊驱动，主动配合宿主机。
代表：经典 Xen
优点：性能极高，损耗极低
缺点：需要修改操作系统内核，兼容性差

## 操作系统级虚拟化（容器）
不虚拟硬件、不虚拟内核，所有容器共享宿主机内核，只隔离文件、进程、网络、用户。
代表：Docker、LXC
特点：秒级启动、体积小、隔离弱

# Hypervisor 类型
Hypervisor（虚拟机管理器）：负责创建、管理虚拟机的程序

## Type1 裸金属虚拟化（直接跑硬件）
直接运行在物理硬件上，没有宿主操作系统
代表：VMware ESXi、微软 Hyper-V、新版Xen
优点：性能最强、稳定、企业生产首选
缺点：部署复杂、维护成本高

## Type2 宿主型虚拟化（寄居虚拟化）
先装宿主操作系统，再装虚拟化软件
代表：KVM、VMware Workstation、VirtualBox
优点：部署简单、灵活、免费
缺点：依赖宿主系统，稳定性略差

# KVM 
KVM（Kernel-based Virtual Machine）Linux 内核自带的硬件全虚拟化模块
Linux 内核直接变身 Hypervisor（Type2 虚拟化）

KVM 的作用：宿主机是 Linux，在这个 Linux 系统里面，再创建、运行多台独立虚拟机（可以是 Linux，也可以是 Windows）。

## KVM 两大核心组件
- KVM 内核模块：只负责虚拟化 CPU、内存、调度 vCPU
- QEMU 工具：用户态模拟所有硬件（磁盘、网卡、显卡、串口）
KVM 管核心资源，QEMU 管硬件设备

## 管理工具栈
日常不用 QEMU 原生命令，太复杂
virsh / libvirt：统一管理接口
调用链路：virsh → libvirt → QEMU → KVM内核

## KVM 磁盘格式
- raw：裸磁盘，性能高，不支持快照
- qcow2（默认）：稀疏磁盘、按需占用空间、支持快照、压缩

## KVM 核心功能
- 完整虚拟机、独立内核
- 快照、克隆
- 热迁移（Live Migration）：虚拟机不停机跨宿主机迁移
- CPU/内存超配

## KVM 优缺点
✅ 开源免费、内核级、性能极高、稳定、云厂商底层主流
❌ 只能跑在 Linux、配置复杂、资源开销比容器大

# 容器
容器属于**操作系统级虚拟化（OS-level virtualization）**，**不是硬件虚拟化**。
容器不模拟CPU、磁盘、网卡这些硬件，**所有容器共享宿主机的Linux内核**，只对宿主机上的**进程、文件系统、网络、用户、资源**做隔离和资源限制。

容器本质就是**一个被隔离、限制资源的进程组**。
最主流实现：Docker（底层依赖Linux内核特性：Namespace 隔离 + Cgroups 资源限制）

1. **Namespace（命名空间）**：隔离。
让容器内的进程看到独立的：主机名、进程号、文件系统、网络、用户ID。容器里面以为自己是独立系统，但本质只是宿主机上一个进程。
2. **Cgroups（控制组）**：限制资源。
限制容器最多能用多少CPU、内存、磁盘IO，防止单个容器耗尽宿主机资源。

## 容器共享宿主机内核
以 Linux 内核为例，容器镜像只提供隔离的根文件系统（如命令、yum/apt包管理器、程序、配置文件），**镜像不含内核**。
依靠Namespace隔离文件系统、进程、网络等资源，所以容器内可以是CentOS环境（自带yum），宿主机可以是Ubuntu（自带apt），两套包管理器互不干扰。但容器底层只能使用宿主机这一个内核。

1. 无需模拟硬件、不用加载独立内核，容器秒级启动；
2. 资源开销极低，没有虚拟机硬件模拟带来的性能损耗；
3. 镜像体积小，仅打包应用和依赖，不需要打包完整操作系统内核。

## 容器镜像
镜像：**只读的模板**，打包应用程序 + 运行依赖（库、配置、脚本），**不含操作系统内核**。
启动容器，就是基于镜像，在宿主机内核之上，创建一个隔离的进程环境。

## 容器特点
✅ 优点
1. 镜像体积极小：MB级别；虚拟机镜像GB级别
2. 启动极快：秒级启动；虚拟机要开机、加载内核，分钟级
3. 资源开销低：不需要为每个容器分配独立内存、模拟硬件
4. 一次打包，到处运行（镜像可迁移）

❌ 缺点
1. **共享宿主机内核，隔离性弱**。容器逃逸风险，一旦攻破内核，所有容器都受影响。
2. Linux容器只能跑Linux程序，不能直接跑Windows内核程序（不像虚拟机可以跑不同系统内核）。
3. 时间、内核版本等底层信息无法完全隔离。

## 虚拟机(KVM) vs 容器(Docker) 

| 对比维度 | KVM 虚拟机                                                | Docker 容器                                        |
| -------- | --------------------------------------------------------- | -------------------------------------------------- |
| 内核     | **每台虚拟机拥有独立完整操作系统内核**                    | **所有容器共享宿主机Linux内核**                    |
| 隔离级别 | 硬件级强隔离。虚拟机崩溃一般不影响宿主机和其他虚拟机      | 进程级弱隔离。共享内核，内核一旦出事全部容器受影响 |
| 镜像大小 | GB级别，包含完整OS系统                                    | MB级别，只包含应用和依赖，无内核                   |
| 启动速度 | 分钟级，需要BIOS、加载内核、系统初始化                    | 秒级，直接启动进程                                 |
| 资源开销 | 开销大，需要模拟CPU、网卡、磁盘等硬件                     | 开销极低，只是普通进程，几乎无硬件模拟损耗         |
| 支持系统 | 宿主机Linux上，可以创建Linux、Windows等任意操作系统虚拟机 | Linux容器只能跑Linux程序；不能原生跑Windows内核    |
| 底层原理 | KVM+QEMU，模拟完整硬件，硬件辅助虚拟化VT-x/AMD-V          | Linux Namespace(隔离)+Cgroups(限流)                |
| 典型场景 | 需要完整独立操作系统、强安全隔离、异构系统                | 微服务、CI/CD、批量部署应用，快速弹性扩缩容        |
